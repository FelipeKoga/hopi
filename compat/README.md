# compat: Hopi's consumer fixtures

Three small apps that consume Hopi the way an app does: the published artifacts and the
`io.github.felipekoga.hopi` plugin, from the repositories `./gradlew checkPublication` fills
(`build/publication-check`, and `gradle-plugin/build/functional-repo` for the plugin), never Maven
Local. `compat/run.sh` builds them on Hopi's floor, the oldest toolchain README's requirements
name, and on the current one. They are not part of the repository's build or of `./gradlew check`.

## Running the matrix

```bash
./gradlew checkPublication     # publishes what the fixtures consume
compat/run.sh                  # every run; `compat/run.sh floor` or `compat/run.sh current` for one half
```

It prints one `PASS` or `FAIL` line per run and exits 1 if any run failed (2 if it cannot start:
no `checkPublication` output, or no JDK 17). Each run's log is `build/compat/<run>.log`. It uses
JDK 17 (`/usr/libexec/java_home -v 17` when `JAVA_HOME` is unset), the repository's Android SDK
(`local.properties`) when `ANDROID_HOME` is unset, and `--no-daemon` everywhere, so no Gradle
daemon is left behind. A full run takes about three minutes once everything is downloaded.

The floor's runs use Gradle 8.0.2 from `compat/floor-gradle`, a wrapper with no build of its own
(generated by Gradle 8.0.2's `wrapper` task, the distribution's SHA-256 pinned), in a Gradle user
home of their own, `build/compat-home`, which the plugin's `functionalTestFloor` shares. It can be
deleted whole; a full floor run fills it to about 2.3 GB, half of it a copy of Kotlin/Native
2.2.21's distribution that the Kotlin Gradle plugin downloads and unpacks into its caches, next to
`~/.konan`'s. When the plugin's jar changes, the next floor run unpacks another copy into a new
`build/compat-home/caches/transforms-3/<hash>` directory: the older one (its
`transformed/extracted/kotlin-native-prebuilt-macos-aarch64-2.2.21`) is then unused and can be
deleted. The current runs use the repository's wrapper and `~/.gradle`. One fixture by hand,
from the repository's root (for `android`, with `ANDROID_HOME` set or a
`compat/android/local.properties` naming the SDK, which run.sh does not need):

```bash
GRADLE_USER_HOME=build/compat-home compat/floor-gradle/gradlew --no-daemon -p compat/android :app:assembleDebug :app:assembleRelease
./gradlew -p compat/android -Pagp=9.4.0 -Pkgp=2.4.20 :app:assembleDebug :app:assembleRelease
```

## The fixtures

| Fixture | The app | Properties (default) |
| --- | --- | --- |
| `android` | An app module, `floor.app`, with `io.github.felipekoga.hopi` and `debugImplementation` of `hopi-network` and `hopi-perf`, and `hopi { network { … }; perf { autoStart(HopiMonitor.Frames) } }` in its Kotlin DSL script (`.set()`, for Gradle 8.0), declared in the root with AGP and the Kotlin plugin; AGP 8 compiles its Kotlin with `org.jetbrains.kotlin.android`, AGP 9 with its built-in Kotlin. compileSdk 34, minSdk 24, Java and Kotlin at 17, build tools 34.0.0 on AGP 8; the release build minified by R8 with `kotlin.Metadata` kept. It depends on `hopi-api`, `hopi-ktor`, `ktor-client-okhttp` 3.3.3 and OkHttp 4.12.0 (Ktor's 5.2.1 wins), and its `App` calls `HopiRules.list()`, `HopiPerf.screen` and installs Hopi's Ktor plugin on an OkHttp client. `:app:compatReport` prints the Hopi modules and the kotlin-stdlib of each variant's runtime classpath | `-Pagp` (8.0.2), `-Pkgp` (2.2.0) |
| `jvm` | A Kotlin/JVM `application` with `hopi-start`, `hopi-ktor` and `ktor-client-mock` 3.3.3. `main` starts Hopi, checks that no rule exists, adds a mock rule (418), sends one request through Hopi's Ktor plugin to a `MockEngine` that would answer 200, fails unless the rule answered, and exits 0 | `-Pkgp` (2.2.0) |
| `kmp` | A KMP shared module with `jvm()` and an `iosSimulatorArm64` framework, `io.github.felipekoga.hopi` and `hopi-ktor` next to the app's own `ktor-client-core`. The framework links with `-Xpartial-linkage-loglevel=ERROR`, so a symbol of Hopi's klibs that the app's Kotlin/Native, Ktor or stdlib cannot supply fails the link instead of becoming a stub that throws when called | `-Pkgp` (2.4.20), `-Pktor` (3.5.2) |

## The runs

| Run | Gradle | AGP | Kotlin | Ktor | Task | Passes when |
| --- | --- | --- | --- | --- | --- | --- |
| floor android | 8.0.2 | 8.0.2 | 2.2.0 | 3.3.3 | `:app:assembleDebug :app:assembleRelease` | both APKs build; the debug runtime classpath holds `hopi-core` and `hopi-network`, the release one only `hopi-api` and `hopi-ktor`; release's kotlin-stdlib is 2.2.x |
| floor jvm | 8.0.2 | | 2.2.0 | 3.3.3 | `run` | the app exits 0 |
| floor kmp | 8.0.2 | | 2.2.21 | 3.3.3 | `:shared:linkDebugFrameworkIosSimulatorArm64 -Phopi.enabled=true`, then `:shared:linkReleaseFrameworkIosSimulatorArm64` | both link with no `e:` line: Debug with every runtime, Release with none, after the iOS release guard |
| floor kmp, old Kotlin | 8.0.2 | | 2.1.21 | | `help` | the build fails with the plugin's message that it needs the Kotlin Gradle plugin 2.2.0, and nothing in `~/.konan` changes (Kotlin/Native's data directory points into `build/compat-home`) |
| current android | 9.7.1 | 9.4.0 | 2.4.20 | 3.3.3 | as on the floor | the same classpaths |
| current jvm | 9.7.1 | | 2.4.20 | 3.3.3 | `run` | the app exits 0 |
| current kmp | 9.7.1 | | 2.4.20 | 3.5.2 | both links | as on the floor |

The android runs use `--rerun-tasks`, because R8 and lint print their warnings only when they run,
and the line counts them: R8 below 8.10.21 (AGP 8.0's is older) warns that it cannot parse Kotlin
2.2's metadata when the rules keep `kotlin.Metadata`, as the fixture's do (without that rule AGP
8.0.2's R8 printed none), and AGP 8.0's lint prints an `e: … incompatible version of Kotlin` line
for every Kotlin 2 library on the classpath (its own compiler reads metadata up to 1.7.1); neither
fails the build. The kmp runs rerun their link (`--rerun`), so each line is that run's link.

What the floor's runs show: Gradle 8.0's Kotlin 1.8.10 compiles an app's build script against the
plugin's DSL and types; AGP 8.0.2 takes the AARs (`minCompileSdk=34`) and runs the plugin's AGP 8.0
path (the debug variant's bytecode transform, the release guard before `preReleaseBuild`); Kotlin
2.2.0 compiles an Android and a JVM app against Hopi's Kotlin metadata, and the JVM app runs on the
kotlin-stdlib it resolves (2.2.21, which Ktor 3.3.3 asks for); Kotlin/Native 2.2.21 links Hopi's
klibs; and the plugin refuses a KMP module on an older Kotlin Gradle plugin before Kotlin/Native
downloads anything.

What no run shows: an APK or a framework at work (nothing is installed or launched; only the JVM
app runs); Kotlin/Native 2.2.0 to 2.2.20 reading Hopi's klibs (the 2.2.0 run below was not made);
any Xcode but 27.1; the versions between the floor's and the current ones; a KMP module with an
Android target.

Kotlin/Native 2.2.0, by hand, with 5 GB free: the Kotlin Gradle plugin 2.2.0 downloads the 2.2.0
distribution and unpacks it into the Gradle home's caches and into `build/compat-home/konan`, with
its LLVM, all of it under `build/compat-home` (delete `build/compat-home/konan` afterwards):

```bash
GRADLE_USER_HOME=build/compat-home compat/floor-gradle/gradlew --no-daemon -p compat/kmp -Pkgp=2.2.0 -Pktor=3.3.3 \
  -Pkonan.data.dir="$PWD/build/compat-home/konan" -Phopi.enabled=true :shared:linkDebugFrameworkIosSimulatorArm64
```
